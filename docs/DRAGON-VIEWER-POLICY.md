# Dragon Viewer content export review

Reviewed November 9, 2026. Section 2(a) of Linden Lab’s Third-Party Viewer Policy requires the viewer to respect Second Life’s permissions. Section 2(b) requires creator verification for each component exported through functionality that Linden Lab’s viewers lack, including full-permission content. Dragon Viewer verifies that identity by comparing the original inventory item’s grid-supplied creator UUID with the authenticated resident UUID. [Third-Party Viewer Policy](https://secondlife.com/corporate/third-party-viewers) · [Linden Lab policy FAQ](https://wiki.secondlife.com/wiki/Linden_Lab_Official:Third_Party_Policy_and_Viewer_Directory_FAQ#Questions_about_content_export)

| Route | Finding and behavior |
| --- | --- |
| Single inventory texture, PNG or TGA | The official preview saves either format. Dragon Viewer requires Copy, Modify and Transfer in the applicable inventory permissions. It checks the current inventory entry again after the file dialog and before scheduling the write. [Official texture preview source](https://github.com/secondlife/viewer/blob/develop/indra/newview/llpreviewtexture.cpp#L269) · [Official permission selection](https://github.com/secondlife/viewer/blob/develop/indra/newview/llviewerinventory.cpp#L2147) |
| Batch inventory textures, PNG | The official inventory offers **Save Selected As**, and its batch writer saves PNG. Dragon Viewer checks each original inventory item for Copy, Modify and Transfer. [Official texture inventory source](https://github.com/secondlife/viewer/blob/develop/indra/newview/llinventorybridge.cpp#L5841) · [Official batch writer](https://github.com/secondlife/viewer/blob/develop/indra/newview/llpreviewtexture.cpp#L306) |
| Batch inventory textures, TGA | The reviewed official batch writer uses PNG. Dragon Viewer additionally requires the current resident to be the verified creator of every original selected texture. It rechecks the item’s asset UUID, permissions and creator after the folder picker and before scheduling writes. |
| Worn shape sent to Blender | The bridge sends a reference rig and geometry shaped by the worn shape asset. The official viewer’s documented appearance XML dump supplies appearance parameters. The Blender payload extends that capability. Dragon Viewer requires the signed-in resident to own and have created the original worn shape and have Modify rights. It rechecks the worn item and asset identity when data arrives and before handing off the payload over localhost. [Official Develop menu](https://wiki.secondlife.com/wiki/Develop_menu) |
| Blender meshes and PBR materials | The mesh flow takes files from the local Blender scene into Dragon Viewer for preview or upload. The PBR editor saves changes through inventory and shows texture UUID references. The reviewed routes contain no file export of Second Life scene meshes or material payloads. |
| Scripts, snapshots and RAW terrain | Local script saving and external editing have official counterparts. The snapshot route saves a rendered image. The estate terrain route uses the simulator’s existing RAW transfer. [Official script editor source](https://github.com/secondlife/viewer/blob/develop/indra/newview/llpreviewscript.cpp#L1306) · [Official snapshot guide](https://wiki.secondlife.com/wiki/Texture_Windows) · [Official private region guide](https://community.secondlife.com/knowledgebase/english/managing-private-regions-r50/) |
| Outfit backups and pose editor files | Outfit backups serialize inventory references and outfit ordering. Restoring an outfit resolves the references in the user’s own inventory. The pose editor generates its clip data from local authoring state, excluding the inventory animations playing on the avatar. |

The texture comparison used Linden Lab’s public viewer source and texture documentation. The policy review covered source paths and did not exercise a live Second Life session. It does not constitute a viewer-wide compliance review or Linden Lab approval. Linden Lab’s release and distribution requirements also cover viewer identity, user disclosures, Terms of Service acceptance, privacy, installation and removal. [Third-Party Viewer Policy](https://secondlife.com/corporate/third-party-viewers)
